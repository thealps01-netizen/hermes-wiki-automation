# AGENTS.md — Wiki Automation panel

Hermes Desktop plugin: `desktop/plugin.js` (the panel, one file, no build step) and
`dashboard/plugin_api.py` + `dashboard/engine_lifecycle.py` (its backend). The engine it installs lives in
`engine/` (its own README, tests and Turkish-language messages); `engine-release.json` pins its content
digest and is generated by `python tools/engine_release.py`, never edited by hand.

Read before changing anything: `Docs/wiki-automation-notes.md` (why every rule exists; the code carries no
comments on purpose) and `Docs/metro-contract.md` (the binding screen and DOM contract). The gates are
described in `README.md` § Gates and, rule by rule, in `tests/README.md`.

## Setup (fresh checkout)
- Node 22+ and Python 3.11+. `cd tests && npm ci`.
- The Hermes install the gates verify against is found by `tests/env.py` / `tests/env.mjs`
  (`HERMES_HOME`, `HERMES_AGENT_DIR`, `HERMES_PYTHON`, `HERMES_ELECTRON`); with Hermes in its default
  location the defaults resolve. Use `PYTHONUTF8=1` on Windows.

## Validation
Fast gates (run all after any change to `desktop/` or `dashboard/`). On a branch that is not installed, point
`HERMES_HOME` at an empty folder, or the static audit and release gate fail on the installed copy's drift
(`tests/README.md` § "against an isolated HERMES_HOME"); keep `HERMES_AGENT_DIR` on the real core then:
```bash
export HERMES_AGENT_DIR="${HERMES_AGENT_DIR:-$LOCALAPPDATA/hermes/hermes-agent}"
export HERMES_HOME=$(python -c "import tempfile;print(tempfile.mkdtemp(prefix='wa-empty-home-').replace(chr(92),'/'))")
python tests/audit_static.py
(cd tests && python canary_audit.py && python release_gate.py)
python tests/contract_core.py && python tests/contract_core.py --selftest
(cd tests && node render_metro.mjs && node render_check.mjs && node render_health.mjs && node preview.mjs)
```
Unit suite (~6 min), after a backend change. It runs against the bundled engine folder:
```bash
E="$PWD/engine"
python tools/engine_release.py --check   # the manifest must name exactly this folder
CORE="${HERMES_AGENT_DIR:-$LOCALAPPDATA/hermes/hermes-agent}"   # the Hermes core checkout (~/.hermes/hermes-agent off Windows)
PYTHONUTF8=1 PYTHONPATH="$CORE" WIKI_ENGINE_TEST_DIR="$E" "$CORE/venv/Scripts/python.exe" -B -m unittest discover -s tests
```
(`venv/bin/python` off Windows.)
Known failures on `main` (2.5.10) before any change: 2 of 118, both in `test_install_recovery_http`
(`…new_session_recovery_actual_http_same_admin_once`, `…different_admin_refused_then_same_admin_http_resume`;
`REAL_HOST_INITIAL_SCOPE` exit 1 — they need a live desktop host). Compare the failure set before and after
your change; a new failure is yours.

## Looking at the panel
`node preview.mjs` writes one live page per screen state, `tests/preview-metro-<state>.html` (fixture data,
the app's own stylesheet). Open them in a browser; no server is needed. Narrow pane: the Electron gates in
`README.md` § Gates (`shot.cjs … --frame=390`).

## Rules
- A user-visible change adds a `CHANGELOG.md` entry and bumps the version in `plugin.yaml`,
  `dashboard/manifest.json` and the CHANGELOG heading together (the static audit fails otherwise).
- A gate rule that changes keeps a canary in `tests/canary_audit.py` that makes it fail.
- Panel copy is English. The engine's own wording is mapped, never replaced
  (`Docs/wiki-automation-notes.md` § "The check's own wording is mapped, never replaced").
- Never edit the installed copies under the Hermes home (`plugins/wiki-automation`,
  `desktop-plugins/wiki-automation`), the owner's `~/.llmwiki-audit/settings.json`, scheduled jobs or the
  wiki. Never push.
